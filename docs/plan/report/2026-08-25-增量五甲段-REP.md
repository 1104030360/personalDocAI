## 2. 步驟與遇到的問題（含怎麼解決）

每個 phase 都走同一條流程：implementer 照計畫實作（53/55 全程 TDD 先紅再綠）→ 跑全量 →
獨立 reviewer 逐 hunk 審 diff＋與計畫逐字比對 → 有 Critical/Important 就進 fix loop → controller 記帳。

**問題 1（工具層陷阱）**：Phase 52 的 Write 工具把計畫裡的 ` ` 字面跳脫**吃成真的 U+00A0 字元**
（正是計畫特別警告不能發生的事）。implementer 自己抓到，用 `chr()` 組字串還原成 6 個 ASCII 字元並複驗
（literal 3／raw NBSP 0）。後續 phase 的派工契約都加了這條提醒。

**問題 2（測試強度缺口）**：reviewer-53 用變異測試證明「4xx/5xx 時 N 停在『…』不顯示猜的 0」
這個規格行為零驗證（把 `if (!response.ok) return null;` 改掉，7 顆仍綠）。
→ Fix round 1：關鍵行清單補釘該行；implementer 再誠實點出同類的 `.catch` 缺口
→ Fix round 2 一併補釘。複審者自跑 4 種**合法 JS** 變異（return {}、刪 catch、catch→finally、邏輯反轉），
全部變紅，缺口關完。

**問題 3（計畫層的第二層錯）**：Phase 54 的第四條 CSS 是計畫核對時補的
`.fm-image + .fm-option`——reviewer-54 抓到它是**死碼**（fm-image 與①列中間隔著
`<h3 id="fm-title">`，相鄰兄弟選擇器被擋住）。→ Fix round 1 改成 `#fm-title + .fm-option`，
複審驗證：跨過 h3、與原本 `:first-of-type` 命中同一顆元素、實體／待辦／詳情三窗零波及。

**問題 4（併行紀律）**：subagent 平行排程全程遵守兩條鐵律——同一時間至多一份 pytest
（conftest 的 reset_tables 會互相 TRUNCATE 測試庫）；implementer 之間檔案面互斥。
reviewer 們也逐一確認了工作樹裡「別的 phase 的痕跡」不是走私。

## 3. 測試方式

- **TDD**：53／55 先寫測試親眼看紅（53：3 綠 4 紅；55：8 綠 2 紅——第 3 顆是護欄型、一開始就綠是預期），
  再改 HTML 轉綠；52／54 依定稿為純前端零新增測試，以指令型驗收＋既有掃碼測試把關。
- **前端契約測試**（比照既有「片語」測試的做法）：把 HTML 當文字讀進來斷言——四格文字網址逐字、
  「待決定（N）」固定形狀（全形括號＋`…` 初始值）、五頁計數片段六行關鍵行逐字（含兩行行為行）、
  aria-current 每頁恰一格、camera-phone 完全無頂欄、browse 不再是待決定入口（無轉址）、端點仍 20。
- **變異測試**（審查階段）：對關鍵行做合法 JS 變異確認測試真的會紅。
- 瀏覽器互動實測（各 phase §4.x 的人工清單）依產品負責人指示**留給 ★G1 親自做**
  （本 session 不操作瀏覽器；可用 curl 驗的都驗了：六頁 200、N 值 psql=API=10）。
