## 遇到的問題與解法

1. **正式庫與 schema.sql 的欄位「物理順序」不同**（implementer 提報）：`ALTER TABLE ADD COLUMN` 只能追加在最後，正式庫實際順序是 `…embedding, folder_id, 路徑三欄`，與 schema.sql 的排列不同。裁決：**接受**——欄位集合與可空性兩庫一致，全系統查詢皆經 `PHOTO_COLUMNS` 明確列名、無 `SELECT *`，無實際影響；記錄在案防止日後以 pg_dump 文字比對時誤判漂移。
2. **`search_by_metadata` 的 category 仍查自由字串**：符合本 phase「不改對外行為」範圍，category 語意收斂是 Phase 20/21 的事——記錄供銜接。
3. **收件箱不存在時 `folder_id` 落空的理論風險**：三處種子來源（schema.sql／migrate／reset_folders_and_photos）皆保證收件箱存在、`folder_one_inbox` 保證至多一個，路徑不可達，無需處理。
