## 1. 實作邏輯

只有 `push` 觸發、在 `main`、而且 `success` 的那一輪才部署；checkout **CI 測過的那個 SHA**（不是當下的 main）；
QEMU＋buildx 建 `linux/amd64,linux/arm64` 多架構 `cloud-worker` 映像推 ECR（`<sha>`＋`latest`）；
最後只在 EC2 `running` 時用 SSM `systemctl restart personaldocai-worker`（unit 的 `ExecStartPre` 會 `docker pull latest`），
不是 running（stopped／terminated／找不到／變數沒設）一律 `::notice::`＋`exit 0`（D16：Stop 時 CD 仍可 push ECR）。

## 3. 測試方式

- TDD（先紅再綠）＋ 兩輪反向變異；fix round 另做五條「刪真 key、留註解」的有牙證明（修正前 `branches` 那條會假綠、修正後紅）。
- `yaml.safe_load` 結構檢查（七欄位逐字）、`grep -F '${{'` 恰 8 行（來源只有七種可信 context）、零長期金鑰字樣、`bash -n`。
- 全量 `pytest -q` 702／0 skipped（實作者兩次、controller 兩次）；三死埠 702；ruff 綠；端點 22、零 DELETE。
- AWS 權限交叉比對（reviewer）：workflow 用到的每個 API 都在 Phase 93 的 policy 五段裡。
- **沒有真的跑 CD**：`workflow_run` 無法本機模擬，Demo 3 由產品負責人 push 後執行。

## 4. 遇到的問題與解法

| 問題 | 解法 |
|---|---|
| 未錨定 regex 被 deploy.yml 自己的註解餵綠（Important） | R15：`^\s*…\s*$`＋`re.M`；五條刪 key 證明；計畫碼區同步 |
| 找不到實例（92-B Terminate 後 ID 過期）會讓每次 push 都紅，與 §1／README 承諾矛盾 | R16：`2>/dev/null \|\| echo "not-found"` → 走 notice＋exit 0；代價是權限錯也印 not-found（log 看得出） |
| SSM 輪詢 5 分鐘 < unit 啟動預算 600 秒（`systemctl restart` 等 ExecStartPre 鏈） | R17：60×10s，訊息改 10 minutes |
| 計畫 §4.5 ③ `deselected` 算錯（10 vs 實 14） | controller 改計畫；實作者 §10.4 紀錄措辭同步修 |
| origin/main 落後 10 個 commit、CI 自 08-28 沒跑 | 計畫 §4.8 步驟 0 加「第一次 push 可能紅在別處，先修 CI、不動 test.yml」 |

## 6. Demo 3（產品負責人執行；計畫 §4.8 逐步）

1. `git push origin main`（10 個既有 commit ＋ 本輪 commit 一起上；`test` 會跑，**可能紅**——紅了先修 CI，不動 `test.yml`；那一輪 `deploy` 有沒有跑不算數）。
2. `app/workers/cloud_worker.py` 加一行註解 → commit → push → `test` 綠 → `deploy` 綠（七個 step）；最後一步 log `instance state: stopped`＋notice、job 仍綠。
3. `aws ecr describe-images` 看到完整 sha；`latest` 同一份映像。
4. Start 92-A → SSM `docker logs cloud-worker | head -1` 的 `version=` 逐字等於 sha → **Stop**。
