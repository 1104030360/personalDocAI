```text
    只有四種情況不往外丟：get_object 缺 key→None、delete_objects 失敗只 warning、instance_state 查無→"unknown"、壞紙條 warning＋刪＋None
    16 顆手寫 stub 測試零出網；design5 那顆「不准有 boto3」掃碼改成「boto3 必須在，s3fs／minio／google-cloud-storage／flower 仍禁」
84  S3 寄物櫃（controller CLI）：東京 bucket、BPA 四項、SSE-S3、Lifecycle documents/ 2 天；scripts/aws_check.py s3 用 mac 最小權限 key 走 put→get→delete
85  SQS 兩條佇列（controller CLI）：jobs Visibility 900／results 30、保留 4 天、長輪詢 20；aws_check.py sqs 兩條各走 send→receive→delete
86  get_cloud_route() 補 assume（AwsMailbox＋AlwaysRunning＋config 逾時秒；boto3 import 在函式內）；2 顆測試；拆 77 鬧鐘 assume 半邊；LAUNCH.md §9 加 "S3 / SQS layer"
    ★ 真 AWS 逾時煙霧（故意沒有工人）：202 → S3 兩物件、jobs 一則 → 30 秒 fallback=local reason=result_timeout → 本機入庫、S3 清空

```

## 測試方式

- TDD：83 與 86 都有 RED→GREEN→變異證據；84／85 是人工操作 phase（指令→預期輸出→退回方式），驗收＝CLI 輸出與 `aws_check.py` 印 OK。
- 零出網：83 的 16 顆全用手寫 stub（`StubS3`／`StubSqs`／`StubEc2` 記 kwargs）；86 的測試用早綁定取原版 `get_cloud_route` 並側錄 `CloudRoute` 建構子；三死埠一起指顆數不變。
- **真 AWS 煙霧（controller，2026-09-03 01:41〜01:45）**：Ollama 0.33.2 開著（embeddings 本機）；頁首開關撥 cloud（閘門與看圖跟開關走）；`.env` `CLOUD_ROUTE=assume`／`CLOUD_RESULT_TIMEOUT_SECONDS=30`＋restart worker → worker 內 `get_cloud_route()` 回 `CloudRoute`、`available()=True`。
  - 逾時腿：上傳 Pillow 合成收據（內容非敏感）→ **202**；t≈6s S3 `documents/<job>/` 有 `context.json`＋`input.png`，jobs 紙條 body 恰 `{"job_id","s3_key"}`、results 0；log `route=cloud verdict=NON_SENSITIVE`（01:41:26）→ `fallback=local reason=result_timeout`（01:41:59）→ job 刪掉（成功）、正式庫 64→65、S3 documents/ 空。
  - 敏感腿：上傳 Pillow 合成假身分證 → **202** → log `route=local verdict=SENSITIVE` → 該 job S3 前綴零物件 → ~5 秒後入庫（66）。
  - 收尾：`purge-queue` jobs → 60 秒後兩條佇列 0／0；`.env` 改回 `off`／`300`＋restart worker（讀到 `CloudRouteOff`）；開關撥回 local；S3 空。
- 掃碼：boto3 只在 `aws_mailbox.py`（`get_cloud_route` 內部 import）；三個 app 檔零 SQL token；端點 22；`docs/spec/`／compose／`db/`／前端零改動；追蹤檔零帳號 ID／bucket 後綴／佇列 URL。
