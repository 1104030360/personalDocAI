## 5. 遇到的問題與怎麼解決

- **`python -m` 下 INFO 全部消失（真缺陷，測試沒抓到）**：第一次真跑工人時 log 檔 0 bytes，但 `sample` 顯示行程已在 SSL read（＝SQS 長輪詢）。原因：用 `-m` 執行時模組的 `__name__` 是 `"__main__"`，`logging.getLogger(__name__)` 拿到的 logger 不在 `_configure_logging()` 掛 handler 的 `app` 樹下，啟動行／「result.json 已放好」／「收到停止訊號」／「已停止」全被 Python lastResort（只印 WARNING 以上）吞掉；計畫檔那句「名字一定要是 `__name__`（＝app.workers.cloud_worker）」在 `-m` 下不成立。修法：字面名 `logging.getLogger("app.workers.cloud_worker")`；`main()` 缺設定改走 `logger.error` ＋ `SystemExit(1)`；新增一顆 subprocess 測試真的用 `python -m` 跑（`S3_BUCKET=""` 讓它在設定檢查就退出），斷言 stderr 有 `ERROR:     cloud_worker 無法啟動` 這個由 handler 加上的前綴——前綴在就證明 logger 掛在 app 樹下。
- **退避期間 Ctrl+C 要等 25 秒**（reviewer Minor 2）：receive 失敗後先 `sleep(5)` 再回到迴圈頂才看旗標，PEP 475 讓 sleep 收到訊號後續睡。修法：sleep 前先看 `should_stop()`；測試用 `SleepRecorder` 取代 `time`，證明旗標已豎時 `slept == []`（此測試對舊碼真紅）。
- **既有測試的預算要跟著調**：`test_單次例外不會讓主迴圈死掉` 的 `stop_after_rounds(3)`→`(4)`（新的 pre-sleep 檢查多問一次），三個斷言不變；re-reviewer 手動追蹤確認正確。
