## 2. 實作邏輯

- **Ec2Probe 為什麼要快取**：EC2 平常是 Stop 的（design6 D15），「遠端關著」是常態；每張照片都打一次 `DescribeInstances` 是跨海往返又有速率限制，EC2 從 stopped 到 running 本來就要一分鐘，所以 60 秒問一次就夠。快取住在物件身上，所以 `dependencies._ec2_cloud_route()` 用 `@lru_cache(maxsize=1)` 讓整個行程共用一條路（代價：改 `.env` 要 restart worker）。失敗的答案也進快取（AWS 壞掉時不該每張都再撞一次）。`instance_id` 空 → 連問都不問、直接 False 並大聲 warning。
- **時基只有一個**：`Ec2Probe` 直接用 `cloud_ingest._now()`（Phase 79 建的 `time.monotonic` 接縫），TTL 測試用既有的 `advance_clock_frozen` 假裝過了 61 秒。
- **多階段 Dockerfile**：套件與程式碼裝在 `base` 一次；`cloud-worker` 只加 `ARG GIT_SHA`＋`ENV WORKER_VERSION`＋exec-form CMD `python -m app.workers.cloud_worker`（exec form 才讓 `docker stop` 的 SIGTERM 送到 PID 1，Phase 88 的優雅停止與 Phase 91 的 systemd `ExecStop` 都靠它）；`app` 放最後，不帶 `--target` 的 `docker build .` 仍蓋出 app 映像。`.dockerignore` 只多一行 `deploy/`。
- **4 顆掃碼**（`tests/integration/test_design6_error_paths.py`）：三個 stage 名、app 在最後、cloud-worker 帶 ARG GIT_SHA、compose 兩檔恰四服務／無 `target:`／零 AWS 字樣（裁決 R10）。
