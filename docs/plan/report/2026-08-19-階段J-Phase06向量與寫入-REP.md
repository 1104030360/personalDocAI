## 遇到的問題與解法

1. **review 發現（Important）U4 端到端無護欄**：原 smoke 只斷言 `fetch_embedding is not None`；reviewer 以突變證明「退化成 clarify 已否決的『只用 text 產向量』方案」時全套測試仍全綠——根因是既有 fixture 的 metadata 值全是 text 子字串，FakeEmbeddings 的詞集合模型分不出。解法：fix round 補護欄測試（fixture 刻意讓 metadata 詞不出現在 text；容差比對 stored≈merged 且 stored≉text-only），任務書同步 0-4(c)。
2. **任務書兩處小瑕疵（implementer 發現）**：(a) 非互動 shell 沒有 `~/.zshrc` 的 `PGPORT=5433`，驗收 6 的 psql 原文指令會誤連 5432——已改帶 `-p 5433` 執行（5432 的 postgresql@14 全程未被連上），任務書回修；(b) phase-06 的 FakeVLM 程式碼區塊 docstring 與 Phase 5 落地版不同——依「FakeVLM 原封不動」原則保留落地版，任務書回修對齊。
3. **裁定 mutation A 不設護欄**：`embed_documents[0]` 取代 `embed_query` 在假件下值完全相同，殺它只能斷言「呼叫了哪個方法」＝測 mock 行為；「同一轉法」約定改由 code review＋Phase 8 真模型實測把關（ledger 有記錄）。
4. **其餘 5 項 Minor 遞延**（記錄於 ledger／本 REP，供後續 phase 開工前計畫更新取用）：unit 檔 docstring「不碰資料庫」不精確（conftest autouse 連庫清表，Phase 3 設計）；`FakeEmbeddings._slot` 無雜湊碰撞守衛（今日 24 詞實測零碰撞；**Phase 9 擴充字彙前建議加守衛測試**：全字彙落位互異且不佔 slot 0）；`embed_document` 的 unit 測試實質測假件；`content_time` 無法解析的 router 分支無自動化整合測試（行為已手驗正確，**Phase 7 `.feature` 驗收時補**）；空字串/空元素不對稱（VLM 經 pydantic 給 None 觸發不到，依 side project 原則不加防禦碼）。
