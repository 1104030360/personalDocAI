`app/services/gated_ingest.py`（以 Phase 80 落地版實檔為基準，用 Edit 只加 PDF 分支，裁決 R2）：
- `_store_cloud_result` 沿用舊名改成**分流器**（依 `job["content_type"]`，不看工人寫的 `kind`）；原單圖本體改名 `_store_image_result`，函式體一字不動。
- 新增 `_store_pdf_result`：① `pages` 空 → `fail_job(ERROR_PDF_UNREADABLE)`；② 本機 `render_pages` → `page_count`；③ 依 `page` 建 `page_results` dict、頁數對不上先 warning、從 `already_done` 的下一頁續跑、每頁 `_store_pdf_page` 後**同一次** `store.update(pages_done=, photo_ids=)`（PDF 版的「先寫收據」，在整份 cleanup 之前）；④ 0 頁成功 → `ERROR_PDF_ALL_PAGES_FAILED`，否則 cleanup → 刪 staging → 刪 job → log `雲端結果已入庫：N 頁中 M 頁成功`。
- 新增 `_store_pdf_page`：工人沒回／看不懂 → 跳過；本機 `_embed_with_retries`（只重算向量、最多 3 次）→ `insert_photo_with_files(page_bytes, PDF_PAGE_CONTENT_TYPE, …)`；寫檔失敗也只跳過那一頁。
- 三條規則（每頁各自成敗／0 頁成功才整筆失敗／`pages_done` 含跳過頁且與 `photo_ids` 同一次寫）與本機路 `ingest_job._run_pdf_job` **逐字相同**；`ingest_job.py` 零改動。

裁決 R4（順手）：`pdf_service.render_pages(pdf_bytes, scale=DEFAULT_SCALE, *, max_pages=None)`（keyword-only、None＝全部、兩個 `raise` 不動），`VlmGate.classify` 的 PDF 分支改 `render_pages(image_bytes, max_pages=1)[0]`——閘門看第一頁不必把 30 頁全渲染。
