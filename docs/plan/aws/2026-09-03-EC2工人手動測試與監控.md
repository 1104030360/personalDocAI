# EC2 工人：手動測試與監控

給沒碰過 AWS 的人。讀完你會自己開機、看 log、上傳一張圖驗收、關機。

完整契約與費用表在 [`LAUNCH.md` §13](../../../LAUNCH.md#13-cloud-worker-ec2)（英文）。
這份只講「你今天要按的按鈕」。

⛔ 全文只寫**變數名**。不要把實例 id、bucket、key、帳號 id 貼進任何檔案或聊天。
⛔ 這台 Mac 的 zsh **沒把 `#` 當註解**。下面可複製區塊裡沒有 `#`；註解都寫在區塊外面。

---

## 1. 先用一句話搞懂

Mac 負責收檔、隱私閘門、算向量、寫資料庫。
遠端那台虛擬電腦（AWS 叫 **EC2 instance**）只負責**看圖**，看完把文字結果放回寄物櫃。

```
你上傳一張圖
    → Mac 先問：這張敏不敏感？（隱私閘門看圖、不看檔名）
    → 敏感／不確定：整張留在 Mac，遠端完全沒反應（這是對的）
    → 不敏感，而且機器是 running：
          Mac 把檔案放進 S3 置物櫃，再往 SQS 丟一張「去拿」的紙條
          EC2 自己去拿、看圖、放回 result.json
          Mac 算向量、入庫、刪掉置物櫃裡的東西
    → 機器是 stopped：Mac 直接自己看圖（log 會寫 fallback=local）
```

兩台機器、兩種工人，不要搞混：

| 誰 | 在哪 | 做什麼 |
|---|---|---|
| `worker` 容器 | 你的 Mac（Docker） | 閘門、派工、等結果、embedding、寫 Postgres |
| `cloud_worker` | EC2 裡的 Docker | 只看圖，不碰資料庫 |

現在那台是 **CPU 機**（`t3.xlarge`），日常把圖**轉送 ollama.com**。
GPU 機還沒開（配額審核中）。同一台 CPU 機也可以暫時改成自己跑 Ollama，很慢，見 §6。

## 2. 六個詞就夠用

| 白話 | AWS 名稱 | 你要記住的 |
|---|---|---|
| 租來的遠端電腦 | **EC2** | 開著按小時計運算；東京約 **$0.22／小時**。忘關一天 ≈ $5 |
| 關機、硬碟留下 | **Stop** | 日常收工用這個。碟錢還在（30 GB ≈ $2.9／月） |
| 整台連硬碟銷毀 | **Terminate** | ⛔ 對這台 CPU 機**永遠不要按**。不可逆 |
| 不開 SSH 的遠端終端機 | **SSM** Session Manager | 這台機器 inbound 全關，進得去只靠 SSM |
| 置物櫃 | **S3** | 圖只短暫放著，入庫後刪掉 |
| 便利貼佇列 | **SQS** | 兩條：jobs（去做）、results（做完了）。紙條裡沒有影像位元組 |

官方：Stop／Start 與 Terminate 是兩件事。
<https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/Stop_Start.html>
<https://docs.aws.amazon.com/AWSEC2/latest/UserGuide/terminating-instances.html>
SSM：<https://docs.aws.amazon.com/systems-manager/latest/userguide/session-manager.html>

## 3. 兩把鑰匙（一定要分清）

這台 Mac 有**兩個** AWS 身分：

| 誰 | 放哪 | 用途 |
|---|---|---|
| 你（管理員） | `~/.aws` 的 default profile | 你打的每一條 `aws …` |
| 程式（最小權限） | 專案 `.env` 的 `AWS_ACCESS_KEY_ID` | 只有 Docker 裡的 boto3 用 |

`.env` 載進 shell 之後，環境變數會蓋過 `~/.aws`。
所以**每次**要打 `aws` 之前，固定這三行（在專案根目錄）：

```bash
set -a; . ./.env; set +a
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
echo "$AWS_REGION"
```

第三行只會印區域（應是 `ap-northeast-1`）。**不要** `echo` 別的變數、不要 `cat .env`。

確認你是管理員（Arn 結尾應是 `personaldocai-admin`）：

```bash
aws sts get-caller-identity --query Arn --output text
```

不要加 `--profile`。這台機器沒有名叫 `personaldocai-admin` 的 profile。

第一次用 SSM 互動殼需要外掛（每台 Mac 一次）：

```bash
brew install --cask session-manager-plugin
```

## 4. 開機（開始燒錢）

先確認 Mac 的 `app` 與 `worker` 容器是 Up（遠端只看圖；沒有本機 worker，照片不會入庫）。

`.env` 日常應是 `CLOUD_ROUTE=ec2`。若檔裡這個鍵寫了兩次，**後面那行才算數**。
改過 `.env` 一定要重啟本機 worker，否則靜默不生效：

```bash
docker compose -f compose.yaml -f compose.dev.yaml restart worker
```

開 EC2：

```bash
set -a; . ./.env; set +a
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
aws ec2 start-instances --instance-ids "$EC2_WORKER_INSTANCE_ID" --region "$AWS_REGION"
aws ec2 wait instance-running --instance-ids "$EC2_WORKER_INSTANCE_ID" --region "$AWS_REGION"
```

等到 `instance-running` 再等約 **1 分鐘**（systemd 拉映像、起工人）。
第一次全新開機要 5〜10 分鐘；這台已經開過，通常 1〜2 分鐘就收得到工作。

## 5. 監控：兩個地方對看

### 5.1 遠端（那台 VM）

進去（沒有 SSH）：

```bash
aws ssm start-session --target "$EC2_WORKER_INSTANCE_ID" --region "$AWS_REGION"
```

進去之後**一次貼一行**（不要整段帶註解）：

```bash
unset HISTFILE
systemctl status personaldocai-worker --no-pager
sudo docker logs cloud-worker --tail 50
```

第一行必須長這樣（值會變，重點是 `vlm=`）：

`cloud_worker 啟動 version=… vlm=cloud model=…`

- 日常：`vlm=cloud`＝這台把圖轉去 ollama.com
- §6 測試：`vlm=local model=gemma4:e2b`＝這台自己的 Ollama 在看

看完打 `exit`。

不開 session、只想看最後 20 行：

```bash
CMD_ID=$(aws ssm send-command --region "$AWS_REGION" --instance-ids "$EC2_WORKER_INSTANCE_ID" --document-name AWS-RunShellScript --parameters 'commands=["docker logs cloud-worker 2>&1 | tail -n 20"]' --query 'Command.CommandId' --output text)
sleep 5
aws ssm get-command-invocation --region "$AWS_REGION" --command-id "$CMD_ID" --instance-id "$EC2_WORKER_INSTANCE_ID" --query 'StandardOutputContent' --output text
```

### 5.2 本機（Mac 的 Celery worker）

```bash
docker compose -f compose.yaml -f compose.dev.yaml logs -f worker
```

`Ctrl+C` 只離開 log，容器還在。 succeess 時依序應看到：

1. `route=cloud verdict=NON_SENSITIVE`
2. `kind=embed backend=local`（向量永遠在 Mac 算）
3. `雲端結果已入庫：photo_id=…`
4. **沒有** `fallback=`

敏感圖則是 `route=local verdict=SENSITIVE`（或 `UNCERTAIN`），遠端 log 完全沒新行——對的。

## 6. 手動測三條路

上傳**之前**先把網頁頁首「AI 模型」撥到**雲端**。
那顆開關管的是**隱私閘門**用哪顆模型（本機 1〜2 分鐘，雲端不到 1 秒）。
它**不管**遠端工人打哪裡。快照在上傳當下抄進 job，所以要先撥再傳。

測完撥回本機：

```bash
curl -sk -X PUT https://127.0.0.1:8000/settings/ai-backend -H 'Content-Type: application/json' -d '{"backend":"local"}'
```

用**內容真的不敏感**的圖（收據、菜單）。改檔名沒用。
一次一張靜態圖。不要用 PDF 做第一次煙霧（佇列沒有心跳，visibility 900 秒）。

### A. 機器開著、日常 cloud（約 10 秒）

§4 開機 → §5 確認 `vlm=cloud` → 上傳一張收據 → 本機三行依序出現。

### B. 機器關著、fallback（約 1 分鐘）

Stop 之後等 **60 秒**（探測結果快取 60 秒；剛關完可能還以為 running）。
再傳一張。本機應看到 `fallback=local reason=remote_unavailable`，然後 `入庫完成`（不是「雲端結果已入庫」）。

### C. 選配：同一台改 local Ollama（約 2〜15 分鐘）

這不是閘門，只是證明「遠端自己看圖」也通。CPU 上 `gemma4:e2b` 常超過 5 分鐘。

1. Mac `.env` 把 `CLOUD_RESULT_TIMEOUT_SECONDS` 從 `300` 改成 `900`，然後：

```bash
docker compose -f compose.yaml -f compose.dev.yaml restart worker
docker compose -f compose.yaml -f compose.dev.yaml exec worker python -c "from app.core import config; print(config.CLOUD_RESULT_TIMEOUT_SECONDS)"
```

印出 `900` 再繼續。不調的話，Mac 會先 `fallback=local reason=result_timeout`，遠端稍後放好的結果變孤兒。

2. 機器要是 running。SSM 進去改**機器上**的 `/opt/personaldocai/worker.env`（不是 Mac 的 `.env`）：

```
WORKER_VLM_BACKEND=local
OLLAMA_BASE_URL=http://127.0.0.1:11434
VLM_MODEL=gemma4:e2b
```

`VLM_MODEL` **不要**加 `-mlx`（那是 Mac Apple Silicon 標籤）。
`AWS_REGION`／ECR／S3／SQS 那幾行不要動。不要 `cat` 整份檔（裡面有 API key）。

3. 若模型還沒拉過：

```bash
export HOME=/root
sudo ollama pull gemma4:e2b
sudo systemctl restart personaldocai-worker
sudo docker logs cloud-worker --tail 5
```

第一行必須是 `vlm=local model=gemma4:e2b`。沒有模型時 unit 仍會起，但看圖會失敗。

4. 只傳**一張**靜態圖。遠端應出現 `kind=vlm backend=local`；本機仍是 `route=cloud` → `雲端結果已入庫`。

5. **做完一定改回去：** `worker.env` 的 `WORKER_VLM_BACKEND=cloud`；Mac 逾時改回 `300`；兩邊都重啟；頁首撥回本機。⛔ 不要把 900 留過夜。

## 7. 關機（每次收工）

```bash
set -a; . ./.env; set +a
unset AWS_ACCESS_KEY_ID AWS_SECRET_ACCESS_KEY
aws ec2 stop-instances --instance-ids "$EC2_WORKER_INSTANCE_ID" --region "$AWS_REGION"
aws ec2 wait instance-stopped --instance-ids "$EC2_WORKER_INSTANCE_ID" --region "$AWS_REGION"
```

「我是不是忘了關？」——預期是**空表格**：

```bash
aws ec2 describe-instances --region "$AWS_REGION" --filters Name=instance-state-name,Values=running --query 'Reservations[].Instances[].{Id:InstanceId,Type:InstanceType}' --output table
```

關著不是壞掉：`CLOUD_ROUTE=ec2` 時探測說 not running，就走本機，上傳仍是 202。

## 8. 對照表

| 你看到 | 意思 | 怎麼辦 |
|---|---|---|
| `route=cloud` + `雲端結果已入庫` | 遠端看圖成功 | 沒事 |
| `fallback=local reason=remote_unavailable` | 機器沒開，或探測說沒開 | 要走雲端就 Start；要測 fallback 就對了 |
| `fallback=local reason=result_timeout` | Mac 等太久 | local 測試先把逾時調 900；日常應是 300 |
| `route=local verdict=SENSITIVE` | 閘門擋下 | 換一張內容不敏感的圖 |
| 遠端完全沒新 log | 圖沒出門 | 看本機是 SENSITIVE 還是機器 stopped |
| 本機改了 `.env` 行為沒變 | 沒重啟 worker，或 `ec2` 物件被 cache 住 | `restart worker` |
| `AccessDenied` 打在 `aws` | 你還拿著 `.env` 那把程式 key | 再做一次 §3 的 `unset` |
| SSM 連不上 | 機器還在 pending／剛 Start | 再等 30〜60 秒 |
| `nvidia-smi: command not found` | CPU 機本來就沒 GPU | 正常 |

## 9. 永遠不要做

1. `terminate-instances`（這台還要留給之後的 Demo）
2. 再開第二台、開 inbound／SSH 22、配 Elastic IP、建 NAT Gateway
3. 把實例 id／key／bucket 寫進 git 或聊天
4. 重送 GPU 配額申請（`L-DB2E81BA` 已是 `CASE_OPENED`）
