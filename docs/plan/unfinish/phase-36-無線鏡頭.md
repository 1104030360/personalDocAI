# Phase 36：無線鏡頭（design3.md D5／D6、§7）——實作前需產品負責人釐清

> 🎯 快門是**人按的**（Auto Capture 已否決）。第一版對準 iPhone＋電腦同一 Wi-Fi。
> 用途：取代「手機拍完 → AirDrop → 桌面上傳」的搬運。

## ⚠️ 實作前必須先向產品負責人釐清（D6 內部有張力，不猜）

1. **「手機用原生相機 App（不是相簿、不是瀏覽器頁）」與「桌面可 Capture／Retake／切鏡頭／閃光」互斥**：
   - 路線 A（手機主導）：QR 掃了開一個極簡手機頁，頁上唯一按鈕觸發 `<input type="file" capture="environment">`
     → 直接跳**原生相機**拍照（不是相簿）→ 自動上傳到桌面 session。切鏡頭／閃光由原生相機自己提供；
     桌面只負責顯示收到的照片＋「Retake（請手機重拍）」。**最貼近「原生相機」字面，實作最小。**
   - 路線 B（桌面主導）：手機頁用 getUserMedia 開瀏覽器取景器串流給桌面、桌面按 Capture——
     這是「瀏覽器頁當鏡頭」，與 D6 括號「不是瀏覽器頁」矛盾，且 getUserMedia 需要 HTTPS（自簽憑證手續）。
   - 需要拍板：採 A 或 B？（本檔先照 A 起草，若 B 要補 HTTPS 決策。）
2. **手機沒有登入概念（單一使用者系統）**：QR 的配對 token 只是「這台手機是我」的臨時通行證——
   有效期多長？（草案：10 分鐘、單一 session、桌面關頁即失效。）
3. 手機拍的照片走既有 `POST /photos` 全流程（VLM＋三關建議），但**三個彈窗在桌面跳**（手機只當快門）——確認。

## 拆解草案（路線 A；釐清後校準再動工）

1. 後端：`POST /camera/session`（桌面建配對，回 token＋供 QR 的 URL）、`GET /camera/{token}/page`（手機極簡頁）、
   `POST /camera/{token}/photos`（手機上傳，轉呼叫既有上傳流程）、桌面輪詢 `GET /camera/{token}/latest`
   （**同步、無 WebSocket**——design3 D4 純 HTML＋同步不動；輪詢間隔 2 秒）。token 存記憶體（單人單機，重啟即失效，不進資料庫）。
2. 前端：上傳頁加「用手機拍」按鈕 → 顯示 QR（本機產生，不用外部服務；qr 產生器用最小依賴或 `<img>` 呼叫本地端點畫 SVG）＋
   等待畫面；收到照片後走既有三關彈窗鏈；「請手機重拍」按鈕。
3. 手機頁：一顆「拍照」按鈕（file input capture）＋上傳中提示；拍完顯示「到電腦上繼續」。
4. 網路：uvicorn 監聽 0.0.0.0；QR 內容用電腦的區網 IP。

## 驗收清單（草案）

- [ ] iPhone 原生相機拍→桌面 10 秒內看到並跳彈窗鏈；Retake 流程通
- [ ] token 過期／亂 token 一律 404；不影響既有端點與測試
- [ ] 全程無雲端服務、無 WebSocket、無新前端框架
