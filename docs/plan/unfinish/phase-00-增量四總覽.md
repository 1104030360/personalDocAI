## 1. 這次增量在做什麼（新手白話）

design4 寫了三件互不相干、但要照順序做的事，最後再加上一件產品負責人臨時裁決的收尾（第 4 項）：

1. **照片詳情（階段甲）**——現在瀏覽頁的資料夾牆只看得到縮圖，點不動；待辦列點下去會
   **另開一個瀏覽器分頁**丟一張原圖給你，旁邊沒有任何說明文字。做完之後，兩邊點下去都會在
   **同一頁**跳出一顆唯讀彈窗：上面大圖、下面 AI 寫的說明與四個欄位（類別／地點／物品／內容日期）。
   「唯讀」＝只能看，**沒有**改資料夾的按鈕（design2 的「定案不可逆」原封不動）。

2. **AI 計時 log（階段乙）**——現在只有「看圖」那一步的終端機訊息帶秒數，其他四種 AI 呼叫
   （轉向量、判斷查法、產生回答、再建議一個實體）完全沒有。做完之後，每一次**真的打到模型**的
   呼叫都會在終端機留下前後兩行、同一種格式，可以用 `grep "kind=embed"` 之類的方式撈出來看誰慢。

3. **Docker 常駐（階段丙，最後才做）**——目前資料庫是 Homebrew 裝的 `postgresql@17`（跑在 5433 埠），
   伺服器要自己開終端機打 `uvicorn`。做完之後，資料庫與 app 各住在一個 container 裡，
   電腦開機 Docker Desktop 自己把它們拉起來。正式庫的資料會從 brew 搬到 Docker 的
   **named volume**（＝Docker 自己管理、有名字的一塊硬碟空間，container 砍掉重建資料還在）。

4. **規格摘標（Phase 51，最後才做；不在 design4 裡）**——`docs/spec/features/自然語言詢問.feature`
   有兩條 Rule 掛著 `@未實作` 標籤，被測試框架自動跳過（就是 `pytest -q` 尾巴那 **2 skipped**）。
   它們描述的功能（「跟我 MacBook 有關的全部」→ 沿別針找照片、「這週要交什麼」→ 查待辦表）
   其實 **Phase 34 早就做好了**，只是規格自己的例子把到期日寫成 `2026-09-18`——
   那已經**超出「這週」的 7 天範圍**，例子跟它自己的問句互相矛盾，所以當初不敢摘標。
   產品負責人 2026-08-23 裁決：**改掉那個日期之後摘標**。做完 `pytest -q` 就沒有 skipped 了。
   ⚠️ 真的動手時會發現**還要多改一行測試假件**（Phase 51 撰寫時查證出來的第二個絆腳石）：
   規格裡的問句是「這週要交什麼」（**沒有**問號），而 `tests/fakes.py` 的假路由對照表
   登記的是「這週要交什麼**？**」（有全形問號）。假路由是**逐字查表**的，差一個字就查不到、
   丟例外、fallback 成語意查詢——所以只摘標的話，紅的會是「檢索方式不對」而不是日期。
   Phase 51 因此要在那份對照表**新增**一個沒問號的鍵
   （**不准改既有那個**——有兩顆測試真的靠它查表，改掉會連帶弄紅）。
   那動的是**測試假件，不是產品程式碼**——`app/` 底下仍然一行都不動。細節見 `phase-51` §4.3。

> **container／image 是什麼**：image ＝「一份打包好的程式與環境」，像光碟；
> container ＝「用那份 image 實際跑起來的一個行程」，像用光碟開起來的一台機器。
> 同一個 image 可以開很多 container；container 砍掉不影響 image。

> **另外三個詞先有個印象就好**（Phase 49 才會真的用到）：
> **overlay（覆寫檔）**＝再疊一份設定檔上去，後面那份會覆寫前面同名的設定；
> **bind-mount**＝把 Mac 上的某個資料夾「接」進 container 裡，兩邊看到的是同一份檔案；
> **熱重載（`--reload`）**＝uvicorn 盯著程式檔，你一存檔它自己重啟，不必手動重來。

### 3.4 design4 之外的兩項裁決（產品負責人 2026-08-23）

本增量計畫成形後，產品負責人又下了兩項裁決。它們**不在 design4.md 裡**，
寫在這裡是為了讓後人一眼看出「這兩件事的授權來源不是設計文件，是人」。

| # | 裁決 | 落在哪 | 對顆數的影響 |
|---|---|---|---|
| 一 | **`LAN_HOST` 本增量明確不做** | `phase-50` §3「明確不做」最後一列＋§4.3 的替代做法 | 無。收尾一律 **387 passed ＋ 2 skipped**，**沒有 388 這個分岔**（原本的「若做 LAN_HOST 就 +1 顆」但書已移除） |
| 二 | **規格摘標**：`自然語言詢問.feature` 兩條 `@未實作` Rule，**修掉例子裡矛盾的到期日後摘標**（＋`tests/fakes.py` 假路由補一個沒問號的鍵，見下方理由） | 新增的 `phase-51`（增量四最後一個 phase） | 38〜50 期間維持 **2 skipped**；Phase 51 之後變成 **389 passed ＋ 0 skipped**（補的是字典鍵不是測試，所以不是 390） |

**裁決一的理由**（design4 §8.5／§8.7 本來就把 `LAN_HOST` 列為「可選、不是遷移成功的必要條件」）：
鏡頭 QR 猜到 Docker 網橋 `172.x` 的**唯一**起因是「桌面頁用 `localhost` 開」，
改用 `https://<區網IP>:8000` 開頁就沒事，不必為它寫程式與測試。
**但 design4 §8.7 要求的驗證步驟仍然要做**（用區網 IP 開 `camera-desk.html`、
確認 QR 網址是 `192.168.…` 不是 `172.…`）——那是**驗收**，不是 `LAN_HOST`。

**裁決二的理由**：那兩條 Rule 描述的功能（entity pin search／task search）
Phase 34 早就落地並過了真模型煙霧，只是規格檔的待辦例子把到期日寫成 `2026-09-18`，
與問句「這週」的 7 天窗互相矛盾（`CLAUDE.md` 現況段與 phase-44 §8 陷阱 4 都已記著這件事）。
這是 design4 §1.1「規格 `.feature` 本輪不改」的**正式例外**，由產品負責人 2026-08-23 核准
——比照 2026-08-21 核准改 `上傳照片.feature` 的先例，改動要在 `.feature` 檔頭留下核准紀錄。

**裁決二為什麼還要動 `tests/fakes.py`（誠實揭露：這一項超出「只改一格日期」的字面範圍）**：
規格第 100 行的問句是「這週要交什麼」（**沒有**問號），但假路由對照表
（`tests/fakes.py` 的 `DEFAULT_ROUTE_DECISIONS`）登記的是「這週要交什麼**？**」（有全形問號）。
`FakeRouter` 是**逐字查表**，查不到就丟例外 → `route_node` 依設計 fallback 成語意查詢
→ `search_mode` 對不上，日期矛盾根本浮不出來。所以 Phase 51 要**新增**一個沒問號的鍵
（**不准改**既有那個——`test_ask_three_paths.py` 有兩顆測試靠它查表），
方向是**假件對齊規格**，不是規格遷就假件。
動的是測試假件，**產品程式碼 `app/` 一行都不動**；新增字典鍵不會多出測試，
所以最終是 389 而不是 390。

| 項目 | 內容 |
|---|---|

| 沒過會怎樣 | **不准停 brew。** 系統維持現狀（brew 5433 繼續服務），Docker 那邊留在 5434 慢慢查 |
| 卡住時怎麼辦 | ① 先把 5434 的 container 停掉、刪掉那個 volume 重來一次 `pg_restore`（此時 volume 裡只有剛灌的資料，刪掉不心疼——**但要先確認你刪的是 5434 那個，不是正式的**）；② 仍對不上就改用 `~/PersonalDocAI-backup-docker遷移前.sql`（純文字那份）查差在哪；③ 三次都失敗就停手，把差異拿去問產品負責人。**brew 的資料目錄全程不准刪** |

### 後悔藥兩層（design4 §8.8）

丙階段任何一步覺得不對，都可以退回去：

```text
第 1 層（快，30 秒）    docker compose stop db
                       brew services start postgresql@17
                       .env 改回無帳號的舊 URL（postgresql://localhost:5433/PersonalDocAI）
                       → brew 的資料目錄沒被刪，立刻回到遷移前

第 2 層（慢，幾分鐘）   用 ~/PersonalDocAI-backup-docker遷移前.dump 灌回任何一邊
                       （brew 或 Docker 都可以）
```

**沒有新備份時絕對禁止**（design4 §8.8 原文）：`docker compose down -v`、`docker volume rm …pgdata`
——`-v` 與 `volume rm` 都會刪掉 named volume ＝ 刪掉正式庫。
（唯一例外是 G2 沒過、還停在 5434 的那個當下：那時 volume 裡只有剛從備份灌進去的複本，
正本還在 brew 那邊，砍掉重灌是安全的——見上面「卡住時怎麼辦 ①」與 phase-46 §5.4。）

**本增量全程禁止，有沒有備份都一樣**（design4 §8.10）：`brew uninstall postgresql@17`、
刪 `/opt/homebrew/var/postgresql@17`——那是後悔藥第 1 層的本體，第一個穩定週期內一律留著。

## 7. 全域鐵律（每個 phase 的計畫檔都隱含這一節）

1. **順序不可對調**：甲 → 乙 → G1（人）→ 丙 → **51（規格摘標）**。
   前四段的順序出自 design4 §0；**51 不在 design4 §0 裡**，是產品負責人 2026-08-23
   額外裁決追加的（§3.4 裁決二）。G1 前不准建任何丙階段檔案；**51 一定排在最後**——
   它會把 2 skipped 變成 0，提前做會讓 G1（design4 §7）與階段丙驗收（design4 §8.9）的
   「顆數不變」對不上。
2. **G1／G2 是人／資料說了算**，不是實作者的判斷；不得自行勾選、不得繞過。
3. **全程 TDD**：先寫會紅的測試，再寫產品程式碼。前端 phase 依本專案慣例可零新增自動化測試，
   但瀏覽器實操驗收要逐項做完、console 要乾淨。
4. **SQL 只在 `app/repositories/photo_repository.py`**；router 零 SQL；錯誤不吞（500 要帶 traceback）。
5. **禁 `alert`／`confirm`／`prompt`**；彈窗錯誤寫在窗內；動態內容一律 `textContent`。
6. **測試安全網不准弱化**：`reset_tables`（絕不清正式庫）、`wire_fake_ai`（pytest 絕不打真 Ollama）、
   `isolated_data_dir`（pytest 絕不寫專案 `data/`）三條 autouse fixture 一條都不能繞過。
7. **端點清點一律用 `/openapi.json`**，不要用 `app.routes`（FastAPI 0.141 的 `_IncludedRouter` 已知坑）。
8. **`postgresql@14`（5432）是別的專案的**（wanderlove、fse_chat_room），全程不准停、不准改、不准連。
9. **embeddings 永遠本機 `bge-m3`**，不歸 AI 後端開關管——向量必須跟庫裡既有的同源。
10. **不 commit**（沿用產品負責人既有指示：改完先檢視）；`unfinish/` → `finish/` 的歸檔隨 commit 執行。
11. **`docs/spec/` 規格區唯讀**（design4 §1.1「規格 `.feature` 本輪不改」）。
    **唯一例外是 Phase 51**：產品負責人 2026-08-23 核准解除唯讀，
    而且只准動 `自然語言詢問.feature` 的**三處**——刪掉兩個 `@未實作` 標籤、
    改一格到期日、在檔頭**新增**核准紀錄（沒有這段紀錄，後人 `git log` 只會看到
    「有人違規動了唯讀檔」）。其餘一字不動，另外六份 `.feature` 完全不碰（見 §3.4 裁決二）。
    Phase 38〜50 期間 `git status docs/spec/` 必須是**乾淨的**（phase-44 §4.3 有這一項）。
12. **skipped 顆數是驗收基準，不是雜訊**：38〜50 期間一律 **2 skipped**；
    Phase 51 之後一律 **0 skipped**。看到它變成別的數字，代表有人動了 `@未實作` 標籤
    或 `tests/conftest.py` 的 `pytest_bdd_apply_tag`——先查，不要改測試去湊。

## 8. 已知限制（MVP 刻意為之，寫在這裡不寫在程式註解）

- **詳情窗不做上一張／下一張**：design4 沒要求；縮圖牆關掉窗再點下一張就好。
- **詳情窗不顯示釘著的實體**：`GET /photos/{id}` 刻意不回實體清單（design4 §4.4 明文），
  這一版的窗只回答「這張是什麼」，不回答「它跟哪些東西有關」。
- **計時只記秒數，不做統計**：沒有平均值、沒有 P95、不寫進資料庫。要分析就自己 `grep` log。
- **`ok=true` 不代表 AI 答得好**：它只代表「這次呼叫沒有丟例外」。看圖看不懂（422）算 `ok=false`，
  但「模型挑不出實體」回 null 算 `ok=true`（呼叫本身是成功的）。
- **丙階段之後 pytest 仍在 host 跑**（不進 container），連的是 Docker 裡的 `PersonalDocAI_test`。
- **待辦查詢的時間窗只有上界、沒有下界**（Phase 34 既有取捨，Phase 51 只是讓它進規格驗收）：
  `search_tasks` 是 `WHERE due_date IS NOT NULL AND due_date <= due_before`，
  所以「這週要交什麼」連**早就過期**的待辦也會撈出來。本增量**不動它**——
  Phase 51 是改規格例子的日期，不是改程式的窗（想改要另案裁決）。
