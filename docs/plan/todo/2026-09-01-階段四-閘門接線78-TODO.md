## 實作邏輯（新手白話）

Phase 74〜77 做出了閘門（`VlmGate`）與雲端路的替身（`CloudRouteOff`），但**沒有人在用它們**。
本 phase 把它們接到 Celery 上：worker 拿到 job 之後，先呼叫新檔 `app/services/gated_ingest.py` 的
`run_gated_ingest_job()`，由它決定這一筆走哪條路：

```text
run_gated_ingest_job(job_id, *, store, vlm, embeddings, now, gate, cloud)
  job = store.get(job_id)；None → log 後 return
  store.update(status="analyzing")            ← 一進門就標，面板不會停在 queued
  route = job.get("route")
    "local"  → run_ingest_job（崩潰重送，不再問閘門）
    "cloud"  → Phase 80 才有（本 phase 走不到）
    沒有     → verdict = gate.classify(filename=…, content_type=…, load_bytes=lambda: read_staging(...))
               store.update(privacy=verdict.value)
               verdict != NON_SENSITIVE  → route=local、log "route=local verdict=…"、run_ingest_job
               not cloud.available()     → route=local、log "fallback=local reason=remote_unavailable"、run_ingest_job
               否則                      → route=cloud、log "route=cloud verdict=NON_SENSITIVE"、
                                            raise NotImplementedError("Phase 79")   ← 本增量唯二的暫時分支
```

`celery_app.ingest_task` 改呼叫它，多組兩個零件：
`gate=dependencies.build_privacy_gate_for_backend(job["ai_backend"])`（**裁決 R1**：worker 的 `config.AI_BACKEND` 永遠 local，
閘門要跟頁首開關走只能用入列快照）與 `cloud=dependencies.get_cloud_route()`（預設 off → `CloudRouteOff`，每一筆都 fallback ＝ 增量五那條路）。
conftest 的 `跑完任務()` 也改走閘門版；monkeypatch **雙名**蓋 `get_privacy_gate` 與 `build_privacy_gate_for_backend`。

做完使用者感覺不到任何變化（pytest 的 `FakePrivacyGate(UNCERTAIN)`＋`CloudRouteOff` 讓每一筆都走本機）；
差別只在 worker log 多了 `route=local verdict=…`／`fallback=local reason=…` 那一行——那是 design6 §2.1 的**契約字樣**，測試用 `caplog` 逐字釘。
