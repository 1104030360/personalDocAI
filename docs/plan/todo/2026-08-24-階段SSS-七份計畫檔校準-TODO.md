## 1. 為什麼要先校準（＝這一階段存在的理由）

七份計畫檔是 2026-08-23 寫的。**寫完之後專案又動了三件事**，
不校準就照著做，會在三個地方「明明是對的卻被判成錯」：

| # | 計畫檔寫的 | 現在的事實 | 不改的後果 |
|---|---|---|---|
| C1 | `pytest -q` ＝ **387 passed ＋ 2 skipped** | **402 passed ＋ 2 skipped** | 45〜50 每一份的驗收都會「對不上顆數」→ 被誤判成 Docker 搬壞了 |
| C2 | 增量四**全程不 commit**，階段甲乙的 `app/` 變更還躺在工作區 | Phase 38〜44 **已 commit**（`507a18f`，2026-08-23），工作區乾淨 | phase-51 §4.0／§4.5 整套「拍前後快照再 diff」的說明前提錯了 |
| C3 | 閘門 G1 `[ ]` 未勾 | 產品負責人 2026-08-24 以 dev-prompt `phase0824.md` 指示執行 45〜51 ＝ **G1 明示通過** | 45〜50 每一份開頭的門檻框都會擋住自己 |
| C4 | 鏡頭 QR「必須是 `192.168.…`、**不可以是 `172.…`**」 | 本機 en0 ＝ **`172.29.93.122`**（172.16/12 私有網段，是**真的區網 IP**） | 判準直接把「正確的 QR」判成錯；而且 172.29 剛好落在 Docker Compose 預設網段池裡，光看前綴根本分不出來 |
| C5 | 憑證「存在即可」 | `certs/cert.pem` 的 SAN ＝ `172.20.10.6`（**舊 IP**）、`localhost`、`127.0.0.1` | 手機連 `https://172.29.93.122:8000` 會被憑證擋，而錯誤訊息看起來像「網路怪怪的」 |

### 步驟 3：鏡頭 IP 與憑證（實質，phase-48／50）

- phase-50 §4.3／§6／§7 的判準：
  「必須是 `192.168.…`、不可以是 `172.…`」→ **「必須逐字等於 `ipconfig getifaddr en0` 的輸出」**

  所以**只看前綴會誤判**，唯一可靠的判準是跟 `en0` 逐字比對

  附 `openssl x509 -noout -text | grep -A2 "Subject Alternative Name"` 的檢查指令與重簽指令
- phase-50 §4.3：真機驗收前先確認憑證 SAN，並標明**這一項交產品負責人手動**
