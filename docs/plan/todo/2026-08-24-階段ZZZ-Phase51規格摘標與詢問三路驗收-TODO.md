### 為什麼要分三步看紅（而不是一次改好）

摘標之後會踩到**兩個**絆腳石，而且**第一個會遮住第二個**：

```text
① 只摘標           → 紅在 search_mode（'vector semantic search' != 'task search'）
                      真話在 RuntimeError：假路由查不到「這週要交什麼」這個鍵
                      （既有那個鍵多一個全形問號）→ fallback 成語意查詢
                      ★ 日期矛盾這時候還輪不到上場，因為根本沒走到待辦那一路
② 補假路由的鍵      → 紅往後移一步：「回答裡沒有提到『交 Project 2』：查無相關照片。」
                      這才是日期矛盾現形：due 2026-09-18 落在「這週」的 7 天窗外
③ 改日期 → 2026-08-21 → 全綠
```

**一次改好就看不到這條因果鏈**，日後有人動壞了也不知道該從哪裡查。

### 為什麼是 2026-08-21

「這週」的換算鏈：`Given 現在時間 2026-08-18` → `get_today` → `due_before = today + 7` = **2026-08-25**，
SQL 是 `due_date <= due_before`（含當天、沒有下界）。

- `2026-09-18` 出局（比上界晚 24 天）
- **不挑 `2026-08-25`**（上界邊界值）：邊界另有專門測試守著；規格 Example 是「功能長什麼樣」的示範，
  踩在邊界上會讓「有人把 `<=` 改成 `<`」變成**規格驗收**紅，看起來像規格錯了
- **不挑今天或更早**：今天是另一端邊界；更早的日期雖然撈得到，但「這週**要交**什麼」配一個已過期的到期日，讀起來莫名其妙
- **`2026-08-21`**：離今天 3 天、離上界 4 天，兩端都不踩；08-18 是週二、08-21 是週五、該週日是 08-23
  ——所以「往後 7 天」與「到本週日」**兩種定義下都在窗內**
