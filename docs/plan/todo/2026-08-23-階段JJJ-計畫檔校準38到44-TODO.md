## 實作邏輯

計畫檔是今天（2026-08-23）依 `docs/design/design4.md` grill 拍板後產出的，
理論上是新的；但「新」不等於「準」——計畫裡引用了大量**具體的程式碼位置**
（行號、常數、函式名、CSS 選擇器、測試名與基準顆數）。只要其中一個引用跑掉，
照著做的人就會改錯地方。所以校準的做法不是重讀一遍文件，而是：

1. **基準數字實跑**：`pytest -q` 顆數、`/openapi.json` 運算元數，與計畫寫的開工基準比對。
2. **程式碼引用逐點 grep**：計畫裡每一個「打開某檔第 N 行會看到 X」的說法，
   用 `rg`／Grep 實際打到現在的工作區驗證。
3. 只有引用與現況**對不上**時才動計畫檔；對得上就不改（避免為改而改）。
