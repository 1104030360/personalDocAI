## 實作邏輯（新手白話）

單圖的雲端路（79／80）已經整圈通了；PDF 的差別只有一件事：**照片正本是「每一頁的 PNG」，但工人只回「看圖結果」，不回影像。**
所以本機拿到 `result.json` 之後要**自己再拆一次頁**（`pdf_service.render_pages`，純 CPU、幾百毫秒；總覽 §10.2 F），
再用工人回來的 `pages[].page`（頁碼，1 起算）去配對——**不用陣列位置**，順序不保證。

```text
本機                                                     工人（★G1 前＝tests/fakes.py 的假工人）
submit：input.pdf ＋ context.json ──S3──►                  render_pages() 只為了看圖
send_job {job_id, s3_key} ──SQS──►                          一頁一頁看 → result.json
                                                            {"kind":"pdf","pages":[{"page":1,"understood":true,…},
wait_result ◄──SQS── send_result ◄──S3── PutObject          {"page":2,"understood":false,…}]}
   │                                                        （拆不開 → "pages": []）
   ▼
_store_cloud_result（分流器；依 job["content_type"]）
   ├ 單圖 → _store_image_result（＝80 版本體，一字不改）
   └ PDF  → _store_pdf_result
             ① pages 空 → fail_job(ERROR_PDF_UNREADABLE)（與本機路同一句話）
             ② 本機 render_pages() → page_count
             ③ 依 page 配對；從 pages_done 的下一頁接著跑；每頁 _store_pdf_page：
                  工人沒回／看不懂 → 跳過；本機 embed（最多 3 次，只重算向量）→ insert_photo_with_files
                  → store.update(pages_done=第 N 頁, photo_ids=…)   ← 成功或跳過都寫、同一次寫
             ④ 0 頁成功 → fail_job(ERROR_PDF_ALL_PAGES_FAILED)；否則 cleanup → 刪 staging → 刪 job
                  → log「雲端結果已入庫：N 頁中 M 頁成功」

裁決 R4（順手）：render_pages(pdf_bytes, scale, *, max_pages=None)；閘門 VlmGate 的 PDF 分支只渲染第一頁（max_pages=1）
```

三條規則（每頁各自成敗／0 頁成功才整筆失敗／`pages_done` 含跳過頁且與 `photo_ids` 同一次寫）與本機路 `_run_pdf_job` **逐字相同**；`ingest_job.py` 零改動。
