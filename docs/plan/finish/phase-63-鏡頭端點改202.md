# Phase 63：鏡頭端點改 202（快門不必等 VLM）

> 🎯 **提醒：這是 side project，不要過度設計。** 只做本文件寫到的事；想「順便多做一點」的時候，答案一律是「不要」。

> 🎯 **一句話目標：** 讓手機按下快門之後，`POST /camera/{token}/photos` 立刻回 **202**，
> 人可以**馬上拍下一張**——不必等 VLM 把上一張看完（現在要等 2〜5 分鐘）。

**為什麼要做這個：** 無線鏡頭現在是「拍一張、等一張」。
手機按下快門之後，那個 HTTP 請求會一路等到 VLM 看完圖、向量算完、檔案寫完才回 201。
本機 gemma4 實測一張要 64〜88 秒（prompt 變長之後 2〜5 分鐘都有），
所以「連拍」在現在的系統裡根本不存在——你會對著一疊收據，拍一張、等三分鐘、再拍一張。
Phase 62 已經把電腦上傳那一支改成 202；本 phase 把鏡頭這一支接到同一條佇列上，
兩邊走**完全一樣**的路。

**本 phase 是純後端。** 手機頁面要怎麼「拍完立刻允許下一拍」、桌面頁的進度窄條、
桌面不再開歸類彈窗鏈——那些全部是 **Phase 69** 的事。本 phase 做完之後，
手機頁面在瀏覽器上看起來**還是舊的行為**（它自己會等回應），那是預期的。

---

**新名詞先解釋：**

| 名詞 | 白話解釋 |
|---|---|
| **202 Accepted** | 「我收下了，但還沒做完」。回應裡沒有結果，只有一張號碼牌 `job_id`。對比 **201 Created**＝「東西已經做好了，就在回應裡」 |
| **入列（enqueue）** | 把「要做的事」放進排隊清單，讓別人去做 |
| **staging（暫存區）** | `data/staging/{job_id}.jpg`。HTTP 把快門擷到的位元組先寫在這裡，worker 之後從這裡讀 |
| **token** | 掃 QR 配對時拿到的一次性通行證。全在 app 的記憶體裡，10 分鐘失效，重啟就沒了 |
| **latest** | 現在的機制：手機拍完，伺服器把那張的 201 內容暫存在 session 裡，桌面用 `GET /camera/{token}/latest` 取走、開歸類彈窗。**本 phase 之後不再有東西寫進它** |
| **WS（WebSocket）** | 桌面與手機之間那條雙向水管，用來交換 WebRTC 的連線資訊與遙控指令。伺服器只轉發，不解讀 |
| **行為變窄** | 端點還在、路徑不變，但它能回的東西變少了。這裡是「`GET latest` 從『有時 200 有時 204』變成『只會 204』」 |

### 4.1 裁決：`set_latest`／`latest` 保留哪些、拿掉哪些

design5 §5 說「行為變窄」、§1.1 說「`GET latest` 不再承擔剛拍那張的歸類 payload」，
但**沒說刪端點**（端點數 20→22 的算式裡 latest 仍在）。所以：**端點保留、回應收窄。**

具體到每一樣東西，**寫死如下，不要自己再判斷一次**：

| 東西 | 去留 | 理由 |
|---|---|---|
| `GET /camera/{token}/latest` 端點（路徑、方法） | **保留** | design5 §5 只寫「行為變窄」；端點數算式要它 |
| 它的 **404**（token 無效／過期／被汰舊） | **保留，一字不變** | §8 錯誤表第 2 列沒有改 |
| 它的 **204**（沒有已完成的） | **保留，而且變成唯一的成功回應** | §5 明文「沒有已完成的 latest → 維持 204」 |
| `upload_camera_photo` 裡的 `camera_session_service.set_latest(token, response)` 那一行 | **拿掉** | §5 明文「**不再** `set_latest`」。202 當下手上只有一個 `job_id`，根本沒有 `UploadResponse` 可以存 |
| `GET latest` 的 `response_model=UploadResponse` | **拿掉** | 沒有人再寫 latest → 200 那條路永遠走不到。openapi 不該宣告一個永遠不會出現的形狀 |
| `camera.py` 的 `from app.schemas.photo import UploadResponse` | **拿掉** | 上一列拿掉之後這個 import 就沒人用了 |
| router 裡「讀 latest → 有就回 200」那兩行 | **拿掉** | 沒有人寫，就永遠是 `None`；留著只會讓人以為還有 200 這條路 |
| `camera_session_service` 的 `CameraSession.latest` 欄位 | **保留，一個字都不改** | 純記憶體的一個小保管箱，零成本 |
| `camera_session_service.set_latest()`／`get_latest()` | **保留，一個字都不改** | 理由與上一列相同（純記憶體的保管箱，零成本）。**而且**：`tests/unit/test_camera_session_unit.py` 有 5 顆單元測試在驗它們（還沒拍過是空的／設定後拿得回／覆蓋前一張／亂 token 不炸／過期拿不到），保留＝那 5 顆一字不改。本 phase 不製造無謂的紅字；真的要清理，等 Phase 71 全量收尾時連同其他死碼一次處理 |

> 一句話總結：**動 router，不動 service。**
> `camera.py` 不再寫也不再讀 latest；`camera_session_service.py` 那三樣原封不動放著。

            imported.add((a.asname or a.name).split(".")[0])

used |= {n.value.id for n in ast.walk(tree)
         if isinstance(n, ast.Attribute) and isinstance(n.value, ast.Name)}
print("可能沒人用的 import：", sorted(imported - used))

## 7. 常見陷阱

1. **把檢查順序弄反（先格式再 token）。**
   現況已經是對的，本 phase 只要別在重寫時弄反。反了的話，
   陌生人拿亂 token 送一個 `.txt` 會收到 415——等於告訴他「你的 token 其實有效，
   只是檔案格式不對」。`test_亂token加上非法格式回404不是415` 守這件事。

2. **以為 `GET latest` 該由 worker 來寫。**
   不行。worker 是**另一個行程**（Phase 65 起是另一個容器），
   讀不到也寫不到 app 行程記憶體裡的 session。design5 §1.1 明文
   「鏡頭 session 仍在 app 記憶體（worker 不參與配對）」。
   桌面要知道進度，走的是 `GET /ingest-jobs`（Phase 64）＋全站進度面板（Phase 67）。

3. **順手把 `camera_session_service` 的 `set_latest`／`get_latest`／`latest` 刪掉。**
   §4.1 的裁決是**保留**。刪了會連帶弄紅 `tests/unit/test_camera_session_unit.py`
   的 5 顆單元測試，而那 5 顆跟本 phase 要驗的事情一點關係都沒有。
   要清理死碼，等 Phase 71 全量收尾時一起處理。

4. **把 `GET /camera/{token}/latest` 整支刪掉。**
   design5 §5 只說「行為變窄」，**沒說刪**。而且端點數 20→22 的算式裡它仍在——
   刪了會變 21，Phase 64 的清點測試（`assert len(運算元) == 22`）會對不上，
   而那時你會以為是 Phase 64 寫錯了。

5. **`GET latest` 留著 `response_model=UploadResponse`。**
   會有兩個後果：① `/docs` 上寫著「這支會回整份照片內容」，而它永遠只回 204——
   文件說謊比沒有文件更糟；② `camera.py` 得繼續 import `UploadResponse`，
   讓「這一支還跟上傳回應有關」的錯覺留下來。
   `test_latest不再宣告UploadResponse這種回應形狀` 守這件事。

6. **測試忘了跑任務就斷言照片存在。**
   症狀：`count_photos() == 0`，或 `fetch_photo(...)` 回 `None` 之後
   `TypeError: 'NoneType' object is not subscriptable`。
   第一個要檢查的就是「這顆測試有沒有呼叫 `跑完任務()`」。

7. **以為「看不懂 → 422」不見了。**
   沒有不見，是**搬家**了：從 HTTP 的當場回應，變成 worker 跑完之後
   `job["status"] == "failed"`。對外的最終結果一字不變（什麼都不存，design5 D10），
   變的只是「使用者什麼時候知道」。
   `test_看不懂的照片是任務失敗不是HTTP失敗` 就是把這件事寫清楚的。
