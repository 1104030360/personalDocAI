# PersonalDocAI — 設計文件（增量三）：無線鏡頭、實體、待辦

> **一句話：全本地把一張掃描變成「抽屜裡的圖、可選的具名物件、可選的待辦」——三種決定用三個彈窗依序確認後才落庫，然後可以用一句話問。**

> 🎯 **仍是 side project：不要過度設計。** 只做本文件寫到的事。同一個 VLM 看一次、人確認才寫入；不做自動拍、不做第二個模型、不做 agent 自己呼叫工具。

## 2. 流程

```text
進圖（擇一，不是串起來）
  桌面上傳 JPEG/PNG/PDF
  或 無線鏡頭（QR 配對，瀏覽器取景，人按快門，桌面即時預覽）
        │
        ▼
  同一個 gemma4 看一次
  吐出三類建議（都還沒定案）：
    抽屜 1 個、實體 1 個（之後可再要）、待辦 0 或 1 筆
        │
        ▼
  照片進待決定（與 design2 相同，人沒按完也安全）
        │
        ▼
  彈窗 1【抽屜】（design2：關不掉）
    ①採用 ②改選現有 ③自創 ④稍後再說
        │
        ▼
  彈窗 2【實體】
    ①採用這一個建議 ②改選現有 ③自創 ④不釘
    ［再建議一個］→ 同一窗再給下一個建議（可釘多個）
        │
        ▼
  彈窗 3【待辦】（僅當 VLM 判斷有 actionable 才出現）
    建立／略過
        │
        ▼
  結構化欄位 ＋ 向量 ＋（可選）實體連結 ＋（可選）待辦
        │
        ▼
  POST /ask：照片 ／ 某張名片上的圖 ／ 待辦
```

### 2.1 三個彈窗的規則（D9，2026-08-21 記錄）

- **順序固定：** 抽屜 → 實體 → 待辦。不可合併成一個窗、不可對調。
- **抽屜窗** 仍適用 design2：無 ×／Esc／點外；④稍後再說＝抽屜留在待決定，**鏈仍繼續**走到實體窗。
- **實體窗、待辦窗** 可以略過（不釘／不建立）。這兩層**不是**關不掉的強制窗。
- **空關不跳：** 沒有 actionable 就不開待辦窗。實體窗每次掃描都開（可立刻④不釘）；沒有現成實體可建議時，①隱藏，只留 ②③④。
- **待決定 tab：** 點一張還沒走完的照片，仍依同一順序把還沒確認的關補完（抽屜若已定案則跳過彈窗 1）。

```text
三種決定 ≠ 三套分類

  維修發票.jpg
    彈窗1 抽屜 → 收據
    彈窗2 實體 → 我的 MacBook（可再建議、可再釘）
    彈窗3 待辦 → 略過

  Canvas截圖.jpg
    彈窗1 抽屜 → 文件
    彈窗2 實體 → 不釘
    彈窗3 待辦 → 交 Project 2，Sep 18
```

## 3. 範圍

**做**

- 無線原生相機（手動快門）＋既有桌面上傳
- PDF 入庫（頁→圖）
- 抽屜 HITL（既有）＋糾錯 few-shot
- 實體表＋照片連結；彈窗複製資料夾三選項，外加「再建議一個」
- 待辦表；人確認才建
- `POST /ask` 可查實體與待辦
- 瀏覽第三入口「待辦」

**不做**

- 自動拍、第二模型、agent tool calling
- Gmail／Calendar 寫入、雲端 VLM
- 刪除照片、多使用者、持續螢幕錄製
- 把實體做成第二套資料夾

## 4. 名詞

| 名詞 | 意思 |
|---|---|
| 抽屜／資料夾（folder） | 類型。一張圖只能在一個。清單短、幾乎不變。定案後不可再換（design2） |
| 實體（entity） | 真實世界的「那一件東西」（我的 MacBook）。別針，可重疊。清單只在你自創時變長 |
| 待辦（task） | 你確認過的一筆任務。不是待決定裡的照片 |
| 待決定 | 還沒選抽屜的照片（design2 inbox） |
| 建議 | VLM 從**現有清單**挑出的那一個（抽屜或實體）；清單外一律不當成新名字自動寫入 |

---

## 5. 資料關係（概念，不是 schema 定稿）

```text
folder (XOR)          entity (AND，可多個)       task (0 或 1 筆／圖，MVP)
   ▲                        ▲                      ▲
   │                        │                      │
 photo ─────────────────────┴──────────────────────┘
```

類別不會因為每張 scan 而無限增加。變多的是實體（你按自創）和待辦（你按建立），以及掛在某張名片上的照片張數。

## 6. 詢問（D14）

仍一個 `POST /ask`、一問一答、查無不虛構、回答語言跟隨提問。

檢索來源變三路（由路由／檢索層決定，不讓模型自己開工具）：

1. 既有照片條件查／向量查
2. 問到已確認的實體名稱 → 沿別針列出掛著的照片
3. 問到待辦／到期 → 查待辦表

目標問句（驗收用）：

- 「跟我 MacBook 有關的全部」→ 名片上的圖，不靠碰運氣搜字
- 「這週要交什麼」→ 待辦清單，不是猜照片描述
