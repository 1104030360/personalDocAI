## 1. 已拍板決策（2026-08-21 對話）

| # | 決策 | 內容 |
|---|---|---|
| D1 | 彈窗強制 | 上傳後的歸類彈窗**不能關掉**：拿掉 ×、Esc、點暗色區三種關閉方式。唯一的出口是四個明確選項之一 |
| D2 | 稍後再說 | 彈窗新增第四個選項「**稍後再說**」＝照片留在待決定區（不呼叫任何 API，照片本來就在收件箱）。這是「我現在不想決定」的**明確**選擇，取代原本曖昧的關窗 |
| D3 | 定案不可逆 | 照片一旦歸進真資料夾＝定案。**後端擋**：`PATCH /photos/{id}/folder` 只接受「目前還在收件箱」的照片，已定案的照片一律 `409`；歸檔目標也不可以是收件箱（`422`）。**沒有任何後悔藥**（產品負責人明示，含誤點情境） |
| D4 | 瀏覽頁兩個 tab | 瀏覽頁頂部分「**待決定（N）｜資料夾**」兩個 tab，預設落在**待決定**（先處理待辦的檔案櫃心智）；「未分類」不再以資料夾卡片出現（它的內容＝待決定 tab）；資料夾 tab 的縮圖牆**純瀏覽**，照片不可點、不開彈窗 |
| D5 | 待決定 tab 的彈窗 | 點待決定 tab 的照片開同一套彈窗，但**沒有選項①**（AI 建議沒有持久化，也沒有「維持」可言）：只有 ②改選現有 ③自建 ④稍後再說 |
| D6 | 建議＝未分類時 | 上傳彈窗若 AI 建議被 clamp 成「未分類」（不確定），**不顯示選項①**（「採用未分類」的語意已由「稍後再說」承接），提示文字改為「AI 不確定這張要放哪」 |
| D7 | 彈窗的資料夾清單 | ② 的下拉選單**排除收件箱**——定案目標必須是真資料夾（與 D3 的 422 一致） |

## 2. 流程

```
上傳 → 強制彈窗（無 ×／Esc／點外）
   ├─ ①採用建議（建議≠未分類才顯示）─┐
   ├─ ②改選現有（下拉不含未分類）    ├─ PATCH 成功 ＝ 定案 → 進資料夾
   ├─ ③自建新資料夾                  ┘   （embedding 同時重算，design1 §7.3）
   └─ ④稍後再說（不呼叫 API）→ 照片留在收件箱 ＝ 出現在【待決定 tab】
        （關掉整個網頁等中斷情況，照片同樣安全落在待決定——安全網）

瀏覽頁 /ui/browse.html
   ├─ 【待決定（N）】tab（預設）：收件箱照片的縮圖牆
   │      點照片 → 彈窗（②③④，無①）→ 定案 → 從待決定消失、進資料夾
   └─ 【資料夾】tab：資料夾卡片（不含未分類）→ 縮圖牆＝純瀏覽，照片不可點

後端唯一新規則（SQL 不變，router 層檢查）：
   PATCH /photos/{id}/folder
     照片不存在 ────────────── 404（既有）
     照片已定案（不在收件箱）── 409「照片已定案，不可再變更資料夾」★新
     folder_id 不存在 ───────── 404（既有）
     folder_id 是收件箱 ─────── 422「不能歸檔到收件箱」★新
     自建重名 ───────────────── 409（既有）
     其餘 ──────────────────── 200 定案（既有）
```

## 5. 被否決的方案（不要重開）

| 方案 | 為什麼否決 |
|---|---|
| 保留 ×／Esc 關窗 | 曖昧的退出正是搞混的來源；改成明確的「稍後再說」 |
| 定案後可移回待決定（後悔藥） | 產品負責人明示：進資料夾就確定了，不能再動 |
| 已定案照片在資料夾 tab 仍可開彈窗（只是灰掉） | 純瀏覽就是純瀏覽，不留假入口 |
| 為待決定另開端點或資料表 | 收件箱既有機制完全夠用 |
