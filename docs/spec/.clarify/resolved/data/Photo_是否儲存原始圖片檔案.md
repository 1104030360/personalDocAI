# 釐清問題

系統是否儲存原始圖片檔案？（規格僅說儲存「圖片資訊、metadata 與向量」，未明確定義「圖片資訊」是否包含原始圖片檔）

# 定位

ERM：Photo 實體的「圖片資訊」範圍；是否需新增儲存原始檔的屬性（如檔案內容或檔案位置）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 儲存原始圖片檔於資料庫中 |
| B | 原始圖片檔存於檔案系統或物件儲存，資料庫僅記錄檔案位置 |
| C | 不儲存原始圖片檔，僅保留 VLM 轉成的文字、metadata 與向量 |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- ERM：Photo 實體是否新增原始檔相關欄位
- 功能「上傳照片」：後置條件規則（儲存圖片資訊）的具體內容
- 功能「自然語言詢問」：回答中能否附上原始照片
- 架構：儲存層設計（純 PostgreSQL vs 需額外檔案儲存）

# 優先級

High
- 「圖片資訊」是規格明列的儲存項目，其範圍未定義會阻礙資料建模與上傳規則的驗收定義

---
# 解決記錄

- **回答**：C - 不儲存原始圖片檔，僅保留 VLM 轉成的文字、metadata 與向量
- **更新的規格檔**：spec/erm.dbml、spec/features/上傳照片.feature
- **變更內容**：Photo 的 Note 新增已釐清決策「不儲存原始圖片檔案，圖片資訊僅指 VLM 轉成的文字」並移除對應的未明確定義項；text 欄位 note 補明不含原始圖片檔；「上傳照片」第一條規則補明「不含原始圖片檔」
