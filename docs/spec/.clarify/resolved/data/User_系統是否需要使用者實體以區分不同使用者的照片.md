# 釐清問題

系統是否需要「使用者 (User)」實體，以區分不同使用者的照片？（規格例句「**我**最近買過什麼飲料？」隱含「我的照片」概念，但規格未提及使用者資料的持久化）

# 定位

ERM：潛在的 User 實體，以及 User 與 Photo 之間的關係；Photo 實體是否需要擁有者屬性

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 單一使用者系統（demo 定位），不需要 User 實體，所有照片屬於同一人 |
| B | 多使用者，需要 User 實體並建立 User 1:N Photo 關係 |
| C | 多使用者，但由外部機制識別身分，Photo 上僅記錄使用者識別欄位（不建 User 實體） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- ERM：是否新增 User 實體與 User–Photo 關係（A5 關係完整性依賴此答案）
- 功能「上傳照片」：照片是否需綁定上傳者
- 功能「自然語言詢問」：檢索範圍是否需以使用者過濾
- 測試：所有 Example 的 Given 是否需要指定使用者

# 優先級

High
- 影響核心資料建模與所有功能的檢索範圍，屬「影響 × 不確定性」皆高的項目

---
# 解決記錄

- **回答**：A - 單一使用者系統（demo 定位），不建 User 實體，所有照片屬於同一人
- **更新的規格檔**：spec/erm.dbml
- **變更內容**：Photo 的 Note 新增已釐清決策「單一使用者系統：不建立 User 實體，照片不區分擁有者，詢問時不以使用者過濾」
