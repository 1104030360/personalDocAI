# 釐清問題

Photo 是否需要記錄時間資訊，以支援規格例句「我**最近**買過什麼飲料？」的時間性查詢？（目前 Photo 實體沒有任何時間屬性，「最近」無資料可依據）

# 定位

ERM：Photo 實體缺少時間屬性；同時涉及功能「自然語言詢問」對「最近」的解讀

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 記錄上傳時間 |
| B | 記錄照片拍攝時間（由 EXIF 或 VLM 從圖片內容推斷） |
| C | 上傳時間與拍攝/內容時間皆記錄 |
| D | 不記錄時間，「最近」不做時間過濾（交由語意檢索自然處理） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- ERM：Photo 是否新增時間欄位（及其型別表示）
- 功能「自然語言詢問」：時間性問題的檢索條件與「最近」的定義（多久以內）
- 測試：時間邊界 Example（B4 時間邊界覆蓋）

# 優先級

High
- 規格例句直接依賴時間概念，缺少此定義該例句無法實作與驗證

# 依賴/組合

- 建議與「Photo_metadata的具體欄位為何」一併釐清

---
# 解決記錄

- **回答**：上傳時間與內容時間皆記錄（對應本項目選項 C）；時間性查詢（如「最近」）優先以內容時間過濾，內容時間為空時以上傳時間替代
- **更新的規格檔**：spec/erm.dbml、spec/features/上傳照片.feature、spec/features/自然語言詢問.feature
- **變更內容**：Photo 新增 uploaded_at 與 content_time 欄位；Note 新增已釐清決策；「上傳照片」新增記錄上傳時間規則；「自然語言詢問」新增時間過濾優先序規則
- **殘留歧義**：「最近」的具體時間長度仍未量化，建議下輪 Discovery 收錄
