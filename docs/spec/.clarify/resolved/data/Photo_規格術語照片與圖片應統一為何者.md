# 釐清問題

規格中同一概念混用「照片」與「圖片」兩種稱呼，應統一為何者？（另有「向量」與「embeddings」混用，亦一併統一）

# 定位

ERM：Photo 實體名稱與 Note 用詞；Feature 檔案中的描述用詞（C2 術語衝突）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 統一使用「照片」（使用者上傳的視角） |
| B | 統一使用「圖片」（系統處理的視角） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- ERM：Photo 實體 Note 與屬性 note 的用詞正規化
- 功能檔案：`上傳照片.feature`、`自然語言詢問.feature` 的描述與未來 Step 用詞（句型一致性）
- 詞彙表（C1）：以此答案為起點建立標準術語

# 優先級

Low
- 不影響行為定義，但影響規格一致性與後續 StepDef 的重複實作風險

---
# 解決記錄

- **回答**：A - 統一使用「照片」；中文敘述稱「向量／embedding 向量」，欄位名維持 embedding
- **更新的規格檔**：spec/erm.dbml、spec/features/上傳照片.feature
- **變更內容**：全文將概念用語「圖片」正規化為「照片」（「圖片格式」因指檔案格式而保留並加註）；「圖片資訊」改稱「照片資訊」並保留規格原文註記；Note 新增術語統一決策
