# 釐清問題

當 VLM 無法理解圖片內容（或處理失敗）時，系統應如何處理該次上傳？照片的文字與 metadata 是否允許為空？

# 定位

Feature：「上傳照片」三條儲存規則的失敗分支；ERM：Photo 的 text 與 metadata 是否可為空（A3 特殊值處理）

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 視為操作失敗，不儲存任何資料 |
| B | 照片仍儲存，text 與 metadata 允許為空（僅保留可產出的部分） |
| C | 照片儲存並標記為失敗狀態，供後續重新處理（依賴「處理狀態」欄位） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- 功能「上傳照片」：需新增錯誤處理規則與 Example（B5）
- ERM：text、metadata 欄位的空值約束（A3）
- 功能「自然語言詢問」：空內容照片是否參與檢索

# 優先級

Medium
- 影響錯誤處理與欄位空值約束的完整性，不阻礙主流程定義

# 依賴/組合

- 選項 C 依賴「Photo_照片是否具有處理狀態」的答案；建議兩題組合釐清

---
# 解決記錄

- **回答**：A - 視為操作失敗，不儲存任何資料
- **更新的規格檔**：spec/features/上傳照片.feature、spec/erm.dbml
- **變更內容**：「上傳照片」新增規則「VLM 無法理解圖片內容時，上傳失敗且不儲存任何資料」與 1 個 Example（Then 操作失敗、照片數量為 0）；Photo 的 Note 補明不會出現 text 為空的記錄
