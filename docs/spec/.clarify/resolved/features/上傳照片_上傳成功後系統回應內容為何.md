# 釐清問題

上傳照片成功後，系統回應給使用者的內容為何？（規格描述了儲存行為，但未定義上傳的回應）

# 定位

Feature：「上傳照片」缺少「使用者可觀察結果」的後置條件規則

# 多選題

| 選項 | 描述 |
|--------|-------------|
| A | 僅回覆成功與照片識別碼 (id) |
| B | 回覆成功並附上 VLM 理解結果（文字與 metadata），讓使用者立即確認 |
| C | 僅回覆成功（不附任何資料） |
| Short | 提供其他簡短答案（<=5 字）|

# 影響範圍

- 功能「上傳照片」：新增回應規則，Example 的 Then 才有可驗證的資料
- API 設計：FastAPI 上傳端點的 response 內容
- UX：使用者能否立即看到系統對照片的理解

# 優先級

Medium
- 影響上傳功能 Example 的可驗證性（Then 需以資料描述），不阻礙儲存行為定義

# 依賴/組合

- 若選 B，內容依賴「Photo_metadata的具體欄位為何」

---
# 解決記錄

- **回答**：回覆成功並附上照片識別碼、文字描述與 metadata（category、location、items、content_time），對應本項目選項 A/B 之合併（成功＋id＋VLM 理解結果）
- **更新的規格檔**：spec/features/上傳照片.feature
- **變更內容**：新增規則「上傳照片成功後，系統回應照片識別碼、文字描述與 metadata」（Example 由例子蒐集題補齊）
